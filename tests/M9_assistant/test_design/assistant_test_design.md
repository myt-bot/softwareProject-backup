# M9 AI 助手模块测试说明

## 1. 测试目标

验证 AI 助手模块的命令定义、OpenAI Function Calling 工具格式、浏览器命令转发、WebSocket 会话桥接、自然语言对话工具调用循环、前后端命令契约、JWT 用户校验和路由注册是否正确。

测试不连接真实大模型服务，也不启动浏览器。所有 OpenAI 响应、WebSocket 消息和浏览器命令执行结果均使用内存替身或 Mock，以便稳定验证以下业务行为：

1. 命令名称唯一，分类、执行端和参数定义完整。
2. 训练配置、训练等待、系统状态、模型保存等新增命令均正确暴露。
3. 工具定义符合 OpenAI Function Calling 格式。
4. 后端能够将浏览器工具请求下发到对应用户连接，并根据 `call_id` 接收结果。
5. AI 对话能够流式发送回复、执行工具调用，并把工具结果继续提交给模型。
6. 命令模式与 AI 模式复用同一套前端命令分发逻辑。
7. 助手连接必须绑定有效登录用户，且 `/assistant/ws` 路由已注册。

## 3. 测试范围

- 命令定义的名称唯一性、分类、执行端和参数列表。
- 新增浏览器命令是否全部出现在后端命令定义中。
- `set_dataset`、`set_train_config`、`wait_training`、`save_model` 等命令的参数 Schema。
- OpenAI Function Calling 工具结构和 `additionalProperties` 限制。
- 帮助文本是否由命令定义统一生成。
- 系统提示词是否包含项目摘要、关键命令和禁止忙等约束。
- 项目快照中的模型层、连接、校验结果和训练配置摘要。
- 浏览器命令挂起 Future 的登记、兑现和清理。
- 浏览器未连接、命令超时、重复结果和连接替换处理。
- 后端本地命令执行与浏览器命令转发。
- `wait_training` 超时时间边界检查。
- AI 流式文本回复、对话历史写入和最终结束消息。
- 模型工具调用、工具结果回填和非法 JSON 参数处理。
- 空用户消息和模型配置缺失处理。
- 后端浏览器命令与前端分发分支的一致性。
- 命令帮助列表与新增命令的一致性。
- 命令模式和 AI 模式是否共用 `executeAssistantCommand`。
- JWT 令牌对应用户校验。
- `/assistant/ws` 路由注册。

## 4. 不测试的内容

- 不调用真实 OpenAI 或其他兼容大模型 API，不评价模型回答质量。
- 不建立真实网络 WebSocket 连接，只测试会话对象、消息协议和路由注册。
- 不执行真实浏览器画布操作，前端命令契约通过静态读取源码验证。
- 不执行真实模型训练、结构校验、项目保存和模板加载，这些业务由对应 M2、M3、M4、M7 模块测试。
- 不测试 AI 助手面板的像素级样式、动画、拖动和浏览器兼容性。
- 不测试 Nginx 对 `/assistant/ws` 的生产环境反向代理，该项属于 M8 部署验证范围。
- 不向测试代码写入真实 API Key，也不验证浏览器 `localStorage` 的安全性。

## 6. 预期结果

- 后端命令定义、工具 Schema、命令帮助和前端命令分发保持一致。
- 浏览器工具调用能够按用户连接和 `call_id` 完成请求、结果回传及超时清理。
- AI 对话能够以流式消息向前端发送正文，并在需要时执行浏览器工具、回填结果后继续生成回答。
- 非法工具参数、未知命令、离线连接、超时、空消息和配置缺失均返回明确错误或提示，不造成挂起任务泄漏。
- 命令模式与 AI 模式复用同一前端业务逻辑，避免同一命令产生两套行为。
- 助手 WebSocket 使用登录令牌绑定已有用户，路由路径与前端连接地址一致。
- M9 自动化测试共 30 条，应全部通过。

## 7. 异常情况考虑

- 浏览器连接不存在时，工具调用应快速失败，不能无限等待。
- 浏览器已连接但未回传结果时，超时后必须删除对应挂起 Future。
- 同一用户的新连接替换旧连接后，旧连接退出不能误删新连接。
- 重复或过期的 `call_id` 回传应安全忽略。
- `wait_training` 的等待时间必须限制在 1～7200 秒，避免异常长时间占用连接。
- 模型返回非 JSON 工具参数时，不应执行实际命令，应把结构化错误反馈给模型。
- 用户消息为空或模型配置不完整时，不应调用外部模型服务。
- JWT 对应用户已不存在时，即使令牌结构可以解析也必须拒绝连接。
- 前后端新增命令时，应同步更新命令定义、前端分发和帮助数据；契约测试用于及时发现漏项。

## 8. 运行方式

在项目根目录执行：

```powershell
python -m unittest tests.M9_assistant.test_code.test_assistant -v
```

也可使用 pytest：

```powershell
python -m pytest tests/M9_assistant/test_code/test_assistant.py -q
```

测试使用内存 WebSocket 替身和 Mock 模型响应，不需要真实 API Key，不访问外部网络，也不需要启动前端或后端服务。
